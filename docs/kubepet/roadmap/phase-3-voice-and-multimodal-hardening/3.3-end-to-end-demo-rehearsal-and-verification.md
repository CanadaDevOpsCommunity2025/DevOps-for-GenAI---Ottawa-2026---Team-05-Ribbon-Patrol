# 3.3 End-to-end demo rehearsal and verification

## Objective

Prove the shipped experience tells a safe, deterministic story in under 90 seconds.

### Demo script

1. Start with a clean, synchronized branch and a healthy pet.
2. Inject remote commits and uncommitted local work.
3. Request a status report and inspect cited repository evidence.
4. Review the proposed stash-and-pull action and its reversal.
5. Inspect the diff preview and branch trajectory.
6. Confirm the action, then show verified synchronization and preserved work.

Use the Guided Demo bar where available. Keep one presenter responsible for the flow.

### Functional verification

Validate all seven scenarios: Clean, MVP Divergence, Conflict, Detached HEAD, Stale Branch, Unpushed Work, and Unsafe 0%.

Test typed chat roles, image generation and editing, voice conversation, and Live Workspace Mode. Confirm fallback behavior for unavailable voice features.

### Test matrix

For every scenario, confirm the health value, symptom, pet treatment, evidence, safe recommendation, preview behavior, and verified outcome. Unsafe must include its extra risk warning.

For every AI interaction, confirm that responses cite snapshot facts and unsupported output remains explanation-only. For image interactions, confirm preview and approval separation. For voice, confirm permission gating, interruption, fallback, and editable transcripts.

For Live Workspace Mode, test a clean repository, dirty repository, detached HEAD, absent upstream, and non-repository workspace. Confirm no path or Git write escapes the read-only boundary.

### Rehearsal roles and timing

Assign a presenter, observer, and recovery owner. The presenter runs the script. The observer records timing and visible defects. The recovery owner can reset the deterministic scenario.

Run one dry rehearsal and two complete timed rehearsals. Use the same browser profile and demo fixture for final delivery. Record the slowest successful run as the reported duration.

### Defect handling

Block delivery for broken approval gates, ungrounded repository claims, unrecoverable demo state, or build failure. Log other defects with severity, workaround, owner, and follow-up decision.

Do not hide a failed remote integration. Use its documented deterministic fallback and state that behavior accurately during the demo.

### Delivery checks

* Run `npm run lint` with no TypeScript errors.
* Run `npm run build` successfully.
* Verify `/api/health`, `/api/ai/chat`, `/api/git/live-status`, `/api/images/generate`, and `/api/voice/tts`.
* Confirm all Git writes remain behind preview and explicit confirmation.

### Exit criteria

The demo completes twice without manual state repair. Each feature failure has a graceful fallback. No required claim relies on unverified behavior.

### Evidence to capture

Record the build results, endpoint responses, scenario checklist, and final demo duration. Note any deferred issue with its impact and workaround.
