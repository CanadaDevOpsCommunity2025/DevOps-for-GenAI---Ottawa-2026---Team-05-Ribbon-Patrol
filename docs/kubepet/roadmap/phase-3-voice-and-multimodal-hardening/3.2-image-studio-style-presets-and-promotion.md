# 3.2 Image Studio style presets and promotion

## Objective

Make pet asset creation fast while preserving the approved asset workflow.

### Scope

Update `src/components/ImageStudioModal.tsx` and the matching image API integration.

### Preset requirements

Offer a concise set of multi-style presets. Each preset includes a bounded visual prompt suffix and preview label. Support selected aspect ratio, emotion state, and transparent-background preference.

Use the required prompt prefix: _original, friendly Git repository companion; minimalist flat-modern style; no text or logos._

Generated previews remain temporary. The studio shows creation and edit results without replacing active assets.

### Promotion requirements

Provide a one-click **Promote** action for a selected preview. It calls the asset approval endpoint and updates only the pet asset mapping.

Asset mapping supports `healthy`, `attention`, `blocked`, and `unsafe`. Show a documented fallback where a variant is unavailable.

### Preset catalog

Start with a small curated catalog that matches the flat-modern product style. Each preset has a stable identifier, human-readable name, prompt suffix, and preview thumbnail or textual description.

The catalog must not imply licensed-character styles or real-person likenesses. Custom prompts remain bounded by the same moderation and no-logo rules.

Changing a preset, ratio, state, or transparency option invalidates only the unsent generation request. It never removes existing previews or approved assets.

### Preview lifecycle

Each preview shows generation state, selected parameters, and target state mapping. Developers can retry, discard, compare, edit, or promote it.

Promotion updates one selected health-state mapping. It preserves the previous approved asset as a rollback candidate. If the promoted asset lacks a state-specific variant, use the documented fallback with a visible label.

Temporary previews expire after a defined short retention period. Expiration must not remove an already approved asset.

### Error and loading states

Show queued, generating, ready, rejected, expired, and failed states. A provider error offers retry without duplicating the current request. Moderation rejection explains the prompt constraint without exposing provider internals.

### Safety requirements

Reject disallowed prompts before generation. Do not send repository data to image generation or editing endpoints. Preserve the source asset until promotion succeeds.

### Acceptance criteria

1. A developer can generate and edit previews with a selected style.
2. Promotion updates the selected state asset only after approval succeeds.
3. Cancel or retry leaves existing assets unchanged.
4. The studio supports all four health variants or displays a fallback.
5. Image requests contain no repository content.
6. Expired or rejected previews cannot be promoted.
7. Promotion preserves a rollback path to the previously approved asset.

### Verification

Generate, edit, promote, retry, and discard an asset. Confirm each health state resolves to an approved asset or fallback.
