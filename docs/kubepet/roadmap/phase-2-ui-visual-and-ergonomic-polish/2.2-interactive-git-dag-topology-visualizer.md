# 2.2 Interactive Git DAG topology visualizer

## Objective

Replace text-only branch metrics with an understandable commit topology.

### Scope

Update `src/components/RepositoryDrawer.tsx`. Build the view from existing repository snapshot data or deterministic mock graph data.

### Required visualization

Render an SVG commit DAG with:

* Main and feature branch lanes.
* Fork points, local commits, upstream commits, and merge bases.
* Commit nodes with concise labels and status-aware styling.

Support hover or focus details for commit ID, branch, timestamp, and relationship. Clearly mark the checked-out branch and divergence direction.

### Interaction and accessibility

The graph must remain readable at narrow drawer widths. Provide text alternatives for commit relationships. All interactive nodes need keyboard focus and descriptive labels.

Avoid external graph libraries unless they reduce implementation risk. Keep rendering deterministic for demo scenarios.

### Layout rules

Render history in chronological order with the current HEAD easy to locate. Keep branch lanes stable while the drawer is open. Draw connecting edges behind nodes and avoid overlapping labels.

Use a compact graph for small histories. Collapse long, linear runs into an explicit count where necessary. Expanding a collapsed run must not change the meaning of the topology.

The active branch, remote branch, local-only commits, and merge base need separate visual tokens. Use shapes, labels, or patterns in addition to color.

### Data normalization

Each commit needs an identifier, parent identifiers, branch memberships, timestamp, and current-head flag. Missing graph information must render as an explicit incomplete-history state.

Sandbox fixtures provide deterministic nodes. Live Workspace Mode may show a reduced graph when history data is unavailable. The existing text metrics remain the fallback.

### Interaction details

Selecting a node highlights its direct parents and children. Hover, focus, and selection use the same metadata panel. Closing the drawer clears selection.

### Acceptance criteria

1. The graph distinguishes local and upstream commits.
2. Forks, merge bases, and current branch are visually identifiable.
3. Hover and keyboard focus reveal commit metadata.
4. The drawer works with both sparse and diverged histories.
5. Text metrics remain available when the graph cannot render.
6. Linear-history collapse preserves a clear commit count and expansion path.
7. Node selection exposes parent and child relationships without mouse-only interaction.

### Verification

Test clean, behind, ahead, diverged, and detached scenarios. Confirm SVG scales without clipped labels.
