# 2.3 Syntax-colored diff highlighting

## Objective

Make additions, deletions, and conflicts immediately scannable before approval.

### Scope

Update `src/components/PreviewChangesModal.tsx`. Preserve the current line-by-line diff, branch trajectory, atomic steps, and reversal content.

### Rendering requirements

* Addition lines use green foreground or background treatment.
* Deletion lines use red foreground or background treatment.
* Conflict lines use a distinct warning treatment and `!` marker.
* Context lines remain visually quiet.
* File headers and line numbers remain readable.

Use semantic classes or tokens rather than hard-coded inline styles. Do not rely on color alone. Preserve original diff text for copy and screen-reader use.

### Edge cases

Handle empty diffs, long lines, binary-file notices, and malformed diff entries without breaking the modal. Wrap or scroll long lines consistently with the current design.

### Diff parsing rules

Classify each line as file metadata, hunk header, context, addition, deletion, or conflict. Preserve the exact original line text and ordering.

Recognize common conflict markers as conflict lines. Render a conflict summary before the affected hunk. Do not claim a conflict is resolved based on coloring alone.

Show a clear no-file-changes state for metadata-only actions. Binary changes display a notice rather than fabricated line content. Malformed entries use a neutral fallback and remain copyable.

### Accessibility and readability

Use visible prefixes for additions, deletions, and conflicts. Screen-reader text must communicate each line type. Maintain adequate contrast in light and dark theme variants, if supported.

Keyboard navigation moves predictably between files and hunks. Focus indicators remain visible against all diff treatments.

### Performance

Render only the visible portion of unusually large diffs where needed. Preserve complete content through an explicit expand action. Do not delay the confirmation gate while highlighting renders.

### Acceptance criteria

1. Added, removed, and conflict lines have distinct visual treatments.
2. Conflict lines include a non-color indicator.
3. Existing preview details remain visible and selectable.
4. Long and empty diffs render without layout breakage.
5. Contrast meets the app’s accessible UI baseline.
6. Binary and malformed entries render a safe, truthful fallback.
7. Large diffs remain responsive and preserve complete content on expansion.

### Verification

Inspect a mixed diff with additions, deletions, and conflicts. Test keyboard navigation, copied text, and narrow viewport behavior.
