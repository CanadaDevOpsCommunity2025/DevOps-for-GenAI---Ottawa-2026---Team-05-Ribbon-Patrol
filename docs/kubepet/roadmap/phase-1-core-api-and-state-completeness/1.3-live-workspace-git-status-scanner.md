# 1.3 Live workspace Git status scanner

## Objective

Allow developers to inspect the active local repository alongside sandbox presets.

### Scope

Add `GET /api/git/live-status` in `server.ts`. Add the client integration only where required for the Live Workspace toggle.

### Data contract

Return a read-only snapshot with:

* Current branch or detached HEAD state.
* Ahead and behind counts against the configured upstream.
* Dirty files and their status.
* Recent commit identifiers and timestamps when available.

Use a clear unavailable state when no repository or upstream exists.

### Security requirements

* Enable scanning only after the developer selects Live Workspace Mode.
* Restrict commands to an allowlisted workspace root.
* Do not accept arbitrary shell commands or repository paths from the client.
* Use argument-based process execution. Avoid shell interpolation.
* Apply a short timeout and return sanitized errors.
* Never perform Git writes.

### Behavior

The API does not replace sandbox data automatically. The client explicitly selects live or sandbox mode. A failed scan leaves the selected sandbox scenario intact.

### Scan lifecycle

Live Workspace Mode begins only after an explicit toggle. Show that the snapshot is live, read-only, and timestamped. Refresh only on a user action or a bounded polling interval.

The scanner reads branch identity, upstream relationship, working-tree status, and recent history. It normalizes command output into the same repository snapshot shape used by sandbox scenarios.

When a repository has no upstream, return `upstreamUnavailable`. When HEAD is detached, return the commit identity and detached status. When no repository exists, return `repositoryUnavailable`. These are expected states, not server failures.

### File and privacy handling

Return file status and a workspace-relative path only when needed for the UI. Cap the returned dirty-file list and provide a total count. Do not read file contents.

Do not persist live snapshots. Do not send local paths, commit bodies, or file names to Gemini unless the developer requests typed or voice guidance with the existing sanitized-context policy.

### Client integration

The Top Bar displays the active mode and latest refresh state. The repository drawer shows unavailable and stale states without clearing the last valid sandbox view.

Switching back to Sandbox Mode immediately restores the selected preset. It never changes the local workspace.

### Acceptance criteria

### Acceptance criteria

1. A valid repository returns branch, divergence, and dirty-file data.
2. A non-repository workspace returns an actionable unavailable response.
3. Detached HEAD and missing upstream states render safely.
4. The scanner cannot run a caller-provided command or path.
5. Live mode never performs a Git write.
6. The client distinguishes unavailable, loading, stale, and current snapshots.
7. Returned file data is capped and never includes file content.

### Verification

Test clean, dirty, detached, and non-repository workspaces. Confirm `curl /api/git/live-status` returns sanitized output. Run lint and build checks.
