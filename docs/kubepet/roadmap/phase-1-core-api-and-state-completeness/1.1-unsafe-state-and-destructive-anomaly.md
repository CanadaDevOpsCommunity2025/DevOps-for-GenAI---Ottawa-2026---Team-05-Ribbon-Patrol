# 1.1 Unsafe state and destructive anomaly

## Objective

Represent repository conditions that could lose work without intervention.

### Scope

Update `src/types.ts`, `src/data/mockScenarios.ts`, and `src/components/PetStage.tsx`.

Add `UNSAFE_LOSS_RISK_SCENARIO`. Model a destructive force-push warning or an uncommitted rebase hazard.

### Functional requirements

* `computeRepositoryHealth` returns **Unsafe** only at exactly `0%` health.
* Unsafe state includes a destructive-risk symptom and evidence values.
* The state never proposes an automatic Git write.
* Guidance offers recoverable commands only, such as `git stash` or `git reset --keep`.
* The pet becomes still and grayscale. Show a visible alert pulse.
* Existing Healthy, Attention, and Blocked behavior remains unchanged.

### Scenario data

Include a named branch, affected-file count, risk summary, and recovery options. The scenario must show why the action is risky before any command appears.

### State and recovery rules

Unsafe has the highest precedence. It overrides another health level whenever the snapshot identifies an immediate work-loss risk.

The UI must state the risk in plain language. It must identify affected work without exposing sensitive file contents. The pet never returns to Healthy until the state engine receives a verified safe snapshot.

Recovery proposals must be bounded and reversible. They must include expected impact, reversal instructions, and the evidence supporting the recommendation. Examples may include preserving work with a stash or abandoning only uncommitted rebase progress with a safe reset.

Destructive commands require an extra warning in the preview. The confirmation surface must name the potential loss and the available recovery path.

### Visual and interaction details

The Unsafe pet is still rather than animated. Apply grayscale to the mascot and ambient aura. Use a restrained alert pulse that does not create motion overload.

The health chip, stage label, drawer, and chat context must all use the Unsafe label. Do not rely on grayscale or red alone. Provide a text status for screen readers.

### Dependencies

This task supplies the Unsafe fixture used by the guided demo, diff preview, voice fallback, and final scenario verification.

### Acceptance criteria

1. Selecting the unsafe preset renders `0%` health and an Unsafe label.
2. The pet uses grayscale, frozen styling, and an alert treatment.
3. The chat response cites scenario evidence and recommends a reversible recovery.
4. No recovery command executes without the existing preview and confirmation gate.
5. All existing scenario presets still render correctly.
6. Unsafe state takes precedence over lower-severity state signals.
7. The recovery preview states expected impact and reversal before confirmation.

### Verification

Run `npm run lint` and `npm run build`. Manually switch from Unsafe to Healthy and confirm the visual state resets.
